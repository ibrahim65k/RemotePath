# RemotePath Project Blueprint

## Identity
RemotePath — **Discover Online Work. Build Your Path.**

- GitHub owner: ibrahim65k
- Repository: RemotePath
- Expected site: https://ibrahim65k.github.io/RemotePath/
- Audience: people in Egypt exploring global online work opportunities.

## Purpose and principles
RemotePath is an independent English-language educational reference for discovering online professions and understanding their work. It is not a marketplace, recruiter, course platform, assessment, chatbot, or account service. The site provides concise role descriptions; complete explanations are generated by the visitor’s chosen AI assistant from prompts added in Phase 03. No earnings, availability, or job guarantees are claimed.

## Phase 02 catalog
The approved catalog has 229 unique specialization records across 15 stable categories. Each record is available through specialization.html?slug={slug}, and is linked from its primary category page. Descriptions are concise, category counts derive from records, and related roles use stable IDs.

## Features and content strategy
Responsive category and specialization discovery; category-level title/description/tag filtering and sorting; role metadata for relevant tags and work models; role cross-links; working static query-string pages; category search; honest Phase 03 prompt placeholders. Avoid publishing full career roadmaps, salary guidance, claims of job availability, or full profession explanations in the site.

## Architecture
HTML5 pages, modular CSS, vanilla JavaScript, and JSON collections under data/. categories.json and specializations.json are the source of truth. Query strings provide static routes without server rewrites. assets/js/config.js centralizes project deployment details and data-loader.js selects the GitHub Pages repository base path when hosted.

## Current status
Phase 01 foundation and Phase 02 catalog are implemented. Data validation confirms the approved list and record relationships. Browser/device visual testing and a live GitHub Pages deployment have not been completed. Phase 03 is next; do not add its prompts or platform/tool catalog before the user supplies Phase 03 instructions.


## Phase 03 — Prompt and resource systems

The static site now composes a complete standalone English AI-learning prompt from `assets/js/prompt-builder.js` and one profession-specific record per specialization in `data/prompt-guidance.json`. The prompt directs the external assistant to teach in natural Egyptian colloquial Arabic while preserving English professional terminology. The same prompt covers the required role overview, workflows, work models, skills, equipment, English, tools, platforms, realistic earnings, roadmap, practice evidence, first opportunity, career growth, AI impact, risks, visuals, glossary, and action plan.

`data/platforms.json` and `data/tools.json` use canonical IDs and stable references to categories and specializations. Directories are local static JSON views with search and filters. The specialization page links filtered directories and renders its own prompt preview and copy action. No backend, build pipeline, user accounts, or paid dependency was added. Phase 04 adds a client-side global search index across all catalog types.

### Egypt availability and verification

Platform records separate `registrationEligibility`, `currentProjectAvailability`, and `paymentAccessibility`. Values use `verified`, `conditional`, `unconfirmed`, or `not-available`; a working home page is never evidence of Egypt eligibility. Official source links identify the evidence and what it supports. Country/project/payment status can change and must be rechecked before publication updates. Pricing and fee details are not invented; tools whose current pricing was not confirmed display `unconfirmed`.

## Phase 04 architecture update

The global search page indexes categories, specializations, platforms, and tools in the browser from the existing JSON files. Search supports ranking, type/category filters, URL query state, and empty/loading/error/no-result states. The whitelisted data loader caches requests for the page lifetime. SEO metadata and BreadcrumbList structured data update for client-rendered category and specialization routes. The GitHub Pages workflow stages a website-only artifact in _site.
